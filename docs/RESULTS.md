# Results

Every number on this page comes from a stored run in the dogfooding SQLite
database (`data/dogfooding/runs.db`, reproduced by the commands below) or from
an artifact committed under [`artifacts/phase6/`](../artifacts/phase6/).
Nothing here was hand-computed or invented. The runs were executed on
2026-11-18 against the `examples/toy_rag` pipeline with the real
`gemini-3.5-flash-lite` judge.

## Setup

- **Corpus:** the six toy documents (`founding`, `membership`, `returns`,
  `shipping`, `support`, `warranty`) in `examples/toy_rag/docs`, ingested with
  chunk size 400 and overlap 50 — the same chunking the pipeline indexes with,
  so chunk IDs match exactly.
- **Test set:** 15 cases — 6 single-hop, 3 multi-hop, 3 unanswerable,
  3 adversarial — generated by `evalora generate` with seed 42
  ([`artifacts/phase6/test_set.jsonl`](../artifacts/phase6/test_set.jsonl),
  generation report:
  [`generation_report.json`](../artifacts/phase6/generation_report.json)).
  Generation cost: 10,921 tokens (9,335 prompt + 1,586 completion).
- **Pipeline:** `toy_rag` in its healthy configuration: BM25 over the full
  index, top-k 3, extractive answers.
- **Baseline:** the healthy run registered as baseline `main`
  ([`baseline.json`](../artifacts/phase6/baseline.json)).
- **Gate:** `max_drop: 0.05` per metric, 95% paired-bootstrap CI, seed 42.

Per question type:

| --- | --- | --- | --- | --- |
| single_hop | 6 | 1.000 | 0.333 | 1.000 |

Failure categories: `generation_failure` 8, `failed_abstention` 3.

The baseline is deliberately imperfect, and that is worth stating plainly: the
extractive toy answerer quotes the top retrieved chunk, so it is fully
faithful and retrieval is perfect, but it answers only 4 of 12 answerable
questions correctly (it cannot combine chunks for multi-hop questions, and it
never abstains on unanswerable ones). The gate therefore measures
*regressions* from this baseline, not absolute quality.

## Regression experiments

Each experiment restarts the pipeline with one degradation toggle, reruns the
same test set, and gates the result against the baseline
(gate summaries are committed as
[`gate-exp-*.md`](../artifacts/phase6/)).

| Experiment | Pipeline change | Hit rate | Context recall | Correctness | New dominant failure | Gate verdict |
| --- | --- | --- | --- | --- | --- | --- |
| `exp-chunks` | chunk size 400 → 120 | 0.000 | 0.000 | 0.333 | `retrieval_failure` ×8 | **FAILED** (exit 1) |
| `exp-stale-index` | `warranty` doc dropped from index | 0.917 | 0.917 | 0.333 | `retrieval_failure` ×1 | passed (exit 0) |
| `exp-weak-prompt` | answers truncated to 60 chars | 1.000 | 1.000 | 0.333 | none | passed (exit 0) |
| `exp-weak-retriever` | top-k 3 → 1 | 1.000 | 0.875 | 0.333 | none | passed (exit 0) |

- **`exp-chunks` was caught.** The gate failed on context recall
  (−1.000, CI [−1.000, −1.000]) and the attribution named retrieval failure
  for 8 of 12 answerable cases. Re-chunking the index differently from the
  evaluation's gold data also breaks ID matching outright, so this experiment
  models index drift (the pipeline's chunks no longer correspond to the
  evaluation's chunks) more than gradual retrieval decay.
- **`exp-stale-index` passed inside the noise band.** Removing a whole
  document cost exactly one case (recall −0.083, exceeding the 0.05
  threshold), but with 12 paired cases the 95% CI of the paired difference is
  [−0.250, 0.000] — it includes zero, so the gate correctly does not fail on
  what could be chance at this sample size.
- **`exp-weak-retriever` passed for the same reason.** Top-k 1 halves recall
  on multi-hop cases (−0.125 aggregate, CI [−0.250, 0.000]); not
  statistically distinguishable from zero at n = 12.
- **`exp-weak-prompt` moved nothing measurable.** The 60-char truncation
  clipped only the tails of answers that are already ~55–60 characters; a
  per-case comparison shows every answer changed but no correctness label
  flipped. An honest negative result: this specific knob does not degrade
  this specific pipeline; the answers were already short.

The pattern across the four experiments is consistent: with a 15-case test
set the gate fails only when the regression is unambiguous (exp-chunks) and
passes single-case drops that fall inside the paired CI. That is the designed
behaviour — no false failures from run-to-run noise — but it also states the
price: catching subtle regressions needs a larger test set (roughly: enough
cases per document that a per-document loss exits the noise band).

## Limitations

- **The healthy baseline is a weak pipeline.** The extractive toy answerer is
  perfectly faithful but answers only 33% of answerable questions correctly
  and never abstains. The gate detects regressions from a baseline; it does
  not certify absolute quality.
- **15 cases give limited statistical power.** Single-case regressions
  (stale index, top-k 1) fall inside the paired 95% CI and pass by design.
  Per-document losses need enough cases per document to exit the noise band.
- **The weak-prompt knob did not bite.** Truncating ~55–60 character answers
  to 60 characters clips tails only; no correctness label flipped. A
  weaker-prompt experiment needs an LLM-backed pipeline or a shorter cap.
- **`exp-chunks` conflates re-chunking with retrieval decay.** Because chunk
  IDs no longer match the gold set, the collapse to zero measures index drift
  rather than gradual retrieval degradation.
- **No hallucination was observed in dogfooding.** Faithfulness is 1.000 in
  every dogfooding run because extractive answers quote the context; the
  RAGTruth benchmark is what exercises the hallucination path.
- **Judge validation is partial.** The RAGTruth measurement covers 23 of the
  planned 60 items (the free-tier daily quota was exhausted mid-run); the
  confidence intervals are correspondingly wide (F1 0.667 with CI
  [0.333, 0.909]), and the judge's known weaknesses — over-flagging summary
  compression, missing subtle numeric details — are documented in
  [`JUDGE_VALIDATION.md`](./JUDGE_VALIDATION.md).
- **The 100–150-item hand-labelled set is still pending.** The spec requires
  the author's manual labels; no labels were synthesized with an LLM.
- **Costs are reported as $0** because the judge model has no verified price
  entry; token counts are the real usage figures.

## Reproducing

```bash
# 1. healthy pipeline (chunking must match the eval config: 400/50)
uv run python -m examples.toy_rag.app &

# 2. test set + baseline
evalora generate --config examples/evalora.yaml --out test_set.jsonl
evalora run --config examples/evalora.yaml --tests test_set.jsonl --run-name healthy-baseline
evalora baseline set --run healthy-baseline --as main
evalora baseline export --run healthy-baseline --out baseline.json

# 3. break the pipeline and gate it
TOY_RAG_CHUNK_SIZE=120 TOY_RAG_CHUNK_OVERLAP=20 uv run python -m examples.toy_rag.app &
evalora run --config examples/evalora.yaml --tests test_set.jsonl --run-name exp-chunks
evalora gate --run exp-chunks --baseline main

# 4. judge validation on the RAGTruth subset
evalora validate-judge --labels artifacts/phase6/ragtruth_prefix_labels.jsonl --dataset RAGTruth
```

The committed artifacts under [`artifacts/phase6/`](../artifacts/phase6/) —
test set, generation report, baseline export, per-experiment gate summaries,
both HTML reports, and the RAGTruth labels plus validation JSON — are the
traceable record of every number on this page.
